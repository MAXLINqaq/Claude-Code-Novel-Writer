# 协作协议

## 核心原则

**用户主导创作，AI 提供专家辅助。**

Claude Code Novel Writer 不是自动写作机。它是一套分层专家系统，在用户的主导下进行规划、写作、审查与迭代。用户随时拥有最终决策权。

## 五阶段协作流程

每个任务遵循：

```
Question -> Options -> Decision -> Draft -> Approval
```

### 1. Question（提问）

智能体首先理解需求，通过提问澄清：
- 当前创作目标是什么？
- 已有哪些素材？
- 约束条件是什么？
- 用户的偏好和风格倾向？

### 2. Options（选项）

智能体呈现 2-4 个可行的方案，每个方案包含：
- 方案概要
- 优势分析
- 风险/代价
- 推荐场景

### 3. Decision（决策）

用户做出选择。智能体不替用户做决定。

### 4. Draft（起草）

智能体根据决策起草内容：
- 在对话中展示草稿，不直接写入文件
- 关键段落或完整内容供用户审阅
- 解释设计决策背后的理由

### 5. Approval（批准）

用户确认后，智能体才执行写入操作：
- 写入前必须明确询问："我可以将内容写入 [文件路径] 吗？"
- 多文件变更需要用户批准完整变更集
- 未经用户指示不得提交 git commit

## 文件写入规范

### 增量写入

创建多节文档时：
1. 立即创建文件骨架（所有章节标题，空内容或占位符）
2. 在对话中逐节讨论和起草
3. 每节获批后立即写入文件
4. 更新 `production/session-state/active.md`
5. 已写入的章节可从上下文中安全压缩

### 文件是记忆，对话是短暂的

- 所有关键决策、状态、进度必须写入文件
- `production/session-state/active.md` 是活检查点
- 在上下文压缩或会话结束后，文件是唯一的持久记忆

## 审查与质量门

### 审查模式

由 `production/review-mode.txt` 控制：

| 模式 | 说明 |
|------|------|
| `full` | 每个工作流步骤都有主管审查 |
| `lean`（默认）| 仅在阶段门控处审查 |
| `solo` | 无审查，最大速度 |

### 阶段门（Gate Check）

每个阶段结束时，必须通过对应审查门才能进入下一阶段：

| 阶段 | 审查门 | 审查内容 |
|------|--------|---------|
| 概念确立 | CD-CONCEPT | 题材、hook、premise、故事引擎 |
| 结构设计 | CD-STRUCTURE | 世界观、人物、总大纲、分卷大纲 |
| 写作准备 | PR-SETUP | 章纲模板、风格指南 |
| 开篇试写 | CD-OPENING | 黄金三章、开篇吸引力 |
| 批量生产 | PR-MILESTONE | 逐章质量、里程碑达成 |
| 精修打磨 | CD-POLISH | 全稿一致性、去AI味 |
| 发布交付 | CD-RELEASE | 最终审查、导出格式 |

## 跨智能体协作

### 垂直委托

Tier 1 -> Tier 2 -> Tier 3

- 领导层做战略决策，部门主管做战术规划，专家做具体执行
- 下级智能体完成任务后向上级汇报
- 冲突上报：当专家之间意见不一致时，上报给部门主管；部门主管之间不一致时，上报给领导层

### 水平咨询

同级智能体之间的协作：
- 剧情主管与人物主管共同审查章节
- 风格主管与去AI味专家联合润色
- 题材主管为特定类型小说提供专家意见

### 冲突解决

1. **事实冲突**（剧情逻辑矛盾）：以剧情主管为准
2. **风格冲突**（文风不一致）：以风格主管为准
3. **创意冲突**（方向分歧）：以创作总监为准，用户拥有最终否决权
4. **进度冲突**（时间/资源）：以生产总编为准

## 用户随时介入

用户可以在任何阶段：
- 推翻任何智能体的决策
- 直接修改任何文件
- 跳过任何审查步骤
- 终止当前工作流，启动新的工作流
- 要求任何智能体重新执行任务

用户的创作意图是最高优先级。
