# 审查工作流

## 审查模式

由 `production/review-mode.txt` 控制：

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| `full` | 每个工作流步骤都有主管审查 | 新手用户、重要项目、关键章节 |
| `lean`（默认）| 仅在阶段门控处审查 | 大多数场景 |
| `solo` | 无审查，最大速度 | 经验丰富的用户、紧急赶稿 |

## 审查类型

### 1. 阶段门审查（Gate Check）

在每个阶段结束时，由 Tier 1 领导层执行：

```
/gate-check [阶段名]
```

审查内容：
- 该阶段的核心产出是否完整
- 产出质量是否达标
- 是否存在阻碍下一阶段的风险
- 用户是否满意

### 2. 完稿审查（Chapter Review）

每章写完后的强制审查：

```
/review-chapter [章节文件路径]
```

六种一致性检查：
1. **剧情逻辑一致性** — 事件前提、决定触发、变化后果
2. **人物一致性** — 五维逐人检查：目标、声音、行为、描写、特质归属（高频Bug：把A的特质写给了B）
3. **情绪与关系一致性** — 情绪来路、关系温度对接
4. **身体与信息状态一致性** — 伤势、秘密、已知信息不丢
5. **场景与转场一致性** — 读者不迷路、余力带过去
6. **章末承接一致性** — 收在变化上、下一章能接住

**任意两项不稳，不回对应专项模块修，不交稿。**

### 3. 专项审查（Specialist Review）

针对特定问题的深度审查：

```
/revise-plot [章节] [问题描述]
/revise-character [章节] [人物名]
/revise-dialogue [章节]
/revise-transition [章节]
```

### 4. 里程碑审查（Milestone Review）

每完成一个关键节点（如一卷、一个高潮）：

```
/milestone-review [里程碑名]
```

## 审查记录

每次审查必须生成审查记录：

```
production/reviews/chapter-XXX-review.md
```

记录内容：
- 审查时间
- 审查者（agent）
- 审查 verdict（通过/需修改/重大修改）
- 发现的问题列表
- 修复建议
- 修复状态跟踪

## 审查 verdict 标准

| Verdict | 说明 | 后续行动 |
|---------|------|---------|
| **APPROVED** | 通过，可以进入下一阶段 | 标记完成，更新 active.md |
| **MINOR REVISION** | 小修，局部问题 | 在当前对话中修复，重新审查 |
| **MAJOR REVISION** | 大修，结构性问题 | 回退到对应专项模块，重新设计 |
| **REJECTED** | 不通过，方向错误 | 返回上一阶段，重新规划 |

## 审查流程图

```
write-chapter 输出初稿
    |
    v
review-chapter（六种一致性）
    |
    +-- APPROVED --> 标记完成，进入下一章
    |
    +-- MINOR REVISION --> 在当前对话修复 --> 重新 review
    |
    +-- MAJOR REVISION --> 路由到 revise-* --> 修复 --> 重新 review
    |
    +-- REJECTED --> 返回大纲/概念阶段，重新规划
```

## 审查效率提示

- **lean 模式下**：信任专家的判断，只在发现问题时才深入审查
- **full 模式下**：每个章节都经过多层审查，质量最高但速度最慢
- **solo 模式下**：完全自主，适合已有成熟流程的用户
- 可以在任何时候切换审查模式：修改 `production/review-mode.txt`
