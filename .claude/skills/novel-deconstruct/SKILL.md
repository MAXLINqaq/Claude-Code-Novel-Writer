# 小说拆解技能

从已有小说正文中，逆向提取出标准化的设计文档，覆盖概念、结构、角色、世界观、技法五个维度。

## 触发条件

- 用户说"拆解这部小说"、"分析这部小说的结构"、"反推设计文档"
- 用户提供了小说正文路径（txt 文件或 manuscript/ 目录）
- 用户想做竞品分析或学习某部小说的写作技法

---

## 执行流程

### 第一步：确认范围

1. 解析用户输入，确定：
   - **小说来源路径**（txt 文件或 `manuscript/` 目录）
   - **拆解范围**：全书 / 指定卷 / 指定章节范围
   - **输出目录**（默认 `deconstruct/<书名>/`）

2. 如果参数不完整，使用 `AskUserQuestion` 补充确认。

3. **一次性读入全部正文**到上下文中（利用 1M 上下文窗口，无需分阶段）。

### 第二步：生成输出目录结构

在输出目录下创建以下子目录（对标仓库 `design/novel/` 和 `outlines/` 结构）：

```
deconstruct/<书名>/
├── README.md                    # 拆解总览
├── design/
│   └── novel/
│       ├── concept.md           # 概念分析
│       ├── pillars.md           # 核心支柱（反推）
│       ├── characters/
│       │   ├── protagonist.md   # 主角档案
│       │   ├── antagonist.md    # 反派/对手档案
│       │   └── supporting/      # 关键配角档案
│       └── worldbuilding/
│           ├── rules.md         # 世界规则
│           ├── factions.md      # 势力/组织
│           ├── locations.md     # 地点
│           └── timeline.md      # 时间线
├── outlines/
│   ├── master-outline.md        # 全书结构总纲
│   └── chapter-outlines/        # 逐章章纲
│       ├── vol01-chapter-001.md
│       └── ...
└── analysis/
    ├── craft-techniques.md      # 技法分析报告
    └── pattern-summary.md       # 模式总结
```

### 第三步：逐项生成（按依赖顺序）

按以下顺序生成，后面的产物可以引用前面的分析结论：

#### 3.1 README.md — 拆解总览

在阅读完全部正文后，从全局视角生成总览，包含：

- 书名、作者、总字数、章节数
- 题材分类 + 子标签
- 一句话总结
- 各维度快速索引（链接到对应文件）

#### 3.2 concept.md — 概念分析

使用模板 `.claude/docs/templates/novel-concept.md` 的结构，从正文中**反推**：

- **题材和消费点**：读者主要来吃什么？爽点在哪？
- **卖点和异常局面**：一句话卖点是什么？主角面临的异常处境？
- **主角眼前最紧迫的问题**：开局问题、代价、时限
- **故事引擎**：靠什么持续推进（升级/调查/身份反打/关系拉扯/倒计时逼迫）
- **Hook 和 Premise**：从开篇300字内提取核心钩子
- **第一卷目标和卷末变化**

#### 3.3 pillars.md — 核心支柱（反推）

从正文中反推作者坚持的创作原则：

- 3-5个支柱（如："主角永远主动"、"力量体系有明确代价"、"感情线服务于主线"）
- 2-3个反支柱（作者明显回避的做法）
- 每个支柱附正文证据引用（章节号+具体段落摘要）

#### 3.4 characters/ — 角色档案

使用模板 `.claude/docs/templates/character-sheet.md` 的结构：

**主角 (protagonist.md)**：
- 基本信息、外貌标签
- 核心驱动力：短/中/长期目标 + 外部/内部阻碍
- 人物弧光：起点→关键转折点→终点
- 声音档案：口头禅、句式偏好、不同情境下的说话方式
- 关系网（与关键角色的关系温度 -10 到 +10）
- 秘密与已知信息

**反派/对手 (antagonist.md)**：同样结构

**关键配角 (supporting/)**：至少涵盖对剧情有实质推动的配角（通常 3-5 个），精简版档案：
- 基本信息、与主角关系、核心目标、关键作用

#### 3.5 worldbuilding/ — 世界观

使用模板 `.claude/docs/templates/worldbuilding-bible.md` 的结构：

**rules.md — 世界规则**：
- 核心规则表（名称/内容/Canon Level/例外代价）
- 每个规则的使用代价和违反代价

**factions.md — 势力/组织**：
- 名称/类型/目标/与主角关系/当前状态/实力评估

**locations.md — 地点**：
- 名称/类型/关键特征/剧情关联/控制权变更

**timeline.md — 时间线**：
- 历史大事记（故事发生前的重要事件）
- 故事时间线（每卷关键事件与世界状态变化）

#### 3.6 outlines/ — 结构大纲

**master-outline.md — 全书总纲**：
- 分卷列表（每卷：卷目标、核心冲突、高潮、卷末变化、章节数）
- 全书三幕结构（如果适用）或网文典型节奏标注（黄金三章/上架节点/大高潮）

**chapter-outlines/ — 逐章章纲**：

使用模板 `.claude/docs/templates/chapter-outline.md` 的结构：

每章包含：
- 本章四问（主角想做什么/谁阻止/局面变成什么/为什么往下看）
- 场景拆分表
- 冲突分析
- 新信息（本章揭示的、对读者的影响、对主角的影响）
- **章末拉力类型**（悬念/危机/反打/承诺/情感钩子）
- 伏笔铺设/回收记录

#### 3.7 analysis/ — 技法分析

**craft-techniques.md**：
- 叙事视角与时态
- 对话风格特征
- 节奏控制：快慢章的分布模式
- 章末钩子的类型偏好和使用频率
- 视角切换策略（多视角时）
- 信息释放节奏（伏笔埋设→回收的间隔规律）
- AI 痕迹评估（如果有）

**pattern-summary.md**：
- 该作品的独特模式（如"每10章一个反转"、"反派从不脸谱化"）
- 可复用的技法提炼
- 对新手作者的建议

---

## 质量守则

1. **以正文为准**：所有分析必须有正文证据支撑，引用章节号或具体段落
2. **保持中立**：这是分析，不是评论。只说"作者选择了什么"，不说"选择好不好"
3. **量化标记**：对可量化的模式给出统计（如"30章中，悬念型钩子占17章，53%"）
4. **完整性优先深度**：先保证所有章节都有章纲，再对关键章做深度分析
5. **使用现有模板**：所有输出对标 `.claude/docs/templates/` 下的模板结构

## 使用示例

```
用户: 拆解 references/神经漫游者.txt
→ 输出到 deconstruct/神经漫游者/

用户: 拆解 manuscript/ 前3章，输出到 deconstruct/draft-review/
→ 仅拆解 chapter-001 到 chapter-003

用户: 分析这部小说的章末钩子模式
→ 仅生成 analysis/craft-techniques.md 的钩子部分
```

---

## 与创作流程的衔接

拆解完成后，可以：
- 将拆解结果作为新小说创作的参考（`/concept-plan` 时参考拆解的概念分析）
- 将技法分析用于 `/polish-chapter` 时的风格校准
- 将章纲模式用于 `/volume-outline` 时的节奏参照
