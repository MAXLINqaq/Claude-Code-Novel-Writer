当此技能被调用时：

1. **解析参数**：确定审查范围（全部大纲 / 指定卷 / 指定章节范围）。
2. **收集上下文**：读取 `design/novel/concept.md`、`design/novel/pillars.md`、`design/novel/characters/` 下的人物档案。
3. **读取大纲**：扫描 `outlines/` 下的总纲、卷纲、章纲文件。
4. **运行七维审查**。
5. **给出 verdict 和修复建议**。

---

### 七维审查

#### 维度 1：概念对齐

检查大纲是否忠实于概念文档的核心定义。

- **题材与消费点**：章纲中的事件是否在持续交付概念文档定义的消费点？如果在"情感拉扯"题材的大纲中连续多章没有人物关系变化，就是偏离。
- **Hook 兑现**：概念文档中的 Hook 是否在黄金三章中得到呈现？如果 Hook 承诺了某种吸引力但前三章没有对应的场景，标记。
- **Premise 一致**：大纲的走向是否符合 Premise 定义的核心设定？如果 Premise 定义了"倒计时逼迫"的前提但大纲中时间压力不体现，标记。
- **故事引擎验证**：概念文档定义的故事引擎（升级/调查/身份反打/关系拉扯/倒计时逼迫）是否在大纲中有持续的推进机制？如果引擎只在开头和结尾出现、中间章节没有引擎驱动的推进，标记。
- **目标长度匹配**：章节数和字数预估是否与概念文档定义的目标长度一致？章节过多或过少都可能说明大纲膨胀或不足。

检查方法：将概念文档的核心定义逐条列出，对照章纲表中的事件，确认每一条在大纲中都有对应。

#### 维度 2：支柱合规

检查大纲是否违反任何支柱或反支柱。

- **支柱符合**：每个支柱是否有对应的正面案例在章纲中体现？例如支柱说"情感优先于情节"，大纲中是否存在"情节强制人物做出不合理行为"的章节？
- **反支柱检查**：每个反支柱定义的"不会做的事"，大纲中是否出现了？例如反支柱说"不会用狗血误会推进剧情"，章纲中是否出现了"因为恰好没听到/没看到导致误会"的桥段？
- **设计测试应用**：将支柱的设计测试应用到章纲的关键决策点——"如果我们争论 X 和 Y，这个支柱说选谁？"——大纲中的实际选择是否符合支柱指向？

检查方法：将每个支柱和反支柱列出来，逐章扫描是否存在违反的情况。注意：不是要求每章都体现所有支柱——而是任何一章都不能违反。

#### 维度 3：人物一致性

检查大纲中的人物状态是否与人物档案一致，以及人物弧光是否按计划推进。

- **目标连续性**：每章的"本章目标"是否符合该人物的短期/中期/长期目标？人物在章节中的行为是否服务于其核心驱动力？
- **声音一致性**：在不同章节中，同一人物的行为模式、语言风格是否保持档案定义的特色？如果档案定义了一个"说话极简"的角色，章纲中是否出现了她大段解释的场面？
- **情绪连续性**：情绪变化是否有触发事件？章纲中的情绪变化是否与人物的情绪触发点和恢复方式一致？
- **弧光推进**：人物从起点状态到终点状态的变化，在章纲中是否有渐进式的体现？关键转折点是否安排在了正确的章节？
- **关系温度变化**：关系网定义的温度变化是否在章纲中有对应的事件支撑？是否出现了"温度跳跃"（没有事件支撑的关系突变）？
- **秘密管理**：每个角色的秘密是否在计划的章节中铺设和揭露？揭露顺序是否符合"轻→重"的原则？是否存在秘密被遗忘（在多章中完全没有提及）的情况？

检查方法：为每个人物列出"弧光检查线"——将档案定义的起点、关键转折、终点标注在章纲时间线上，检查每个节点是否有对应的事件。

#### 维度 4：结构完整性

检查分卷和章纲的结构是否完整、合理。

- **卷四件套**：每卷是否有明确的卷目标、卷核心冲突、卷高潮、卷末变化？这四件是否互相关联（高潮是实现目标的关键事件，卷末变化是高湖的后果）？
- **章四件套**：每章是否有明确的本章目标、本章冲突、本章新信息、章末拉力？缺少任何一件都会导致该章缺乏动力。
- **无过渡章**：是否存在"只有过渡功能、没有实际事件和变化"的章节？过渡信息可以压缩到其他章节的开头或结尾，不应独占一章。
- **黄金三章**：前三章是否完成了五个亮相（主角、卖点、第一冲突、阶段目标、追更理由）？
- **高潮位置**：卷高潮是否安排在合理的位置？是否太早（后段无力）或太晚（前面拖沓）？
- **节奏曲线**：冲突的强度是否张弛有度？是否存在连续多章高强度冲突（读者疲劳）或连续多章无冲突（读者流失）？

检查方法：逐章检查四件套是否完整且有意义。注意"本章新信息"是否真的有信息增量——如果某章的新信息在上一章已经暗示过了但没有实质推进，标记为弱信息章。

#### 维度 5：伏笔与回收管理

检查总纲中的伏笔系统是否完整，以及章纲中是否体现了伏笔的铺设和回收。

- **伏笔登记**：总纲中是否有全局伏笔列表？每条伏笔是否标注了铺设章节和计划回收章节？
- **铺设到位**：伏笔的铺设是否在章纲中有对应的新信息？铺设是否足够隐蔽（不是直接告诉读者答案）又足够可感（读者不会完全没注意到）？
- **回收计划**：每条伏笔是否有明确的回收章节？回收是否有冲击力（回收时揭示的信息比铺设时暗示的更多）？
- **无遗忘伏笔**：是否存在铺设了但没有回收计划的伏笔？是否存在回收了但从未铺设的"凭空回收"？
- **伏笔层次**：是否有长线伏笔（跨卷）和短线伏笔（卷内）的合理配比？全是短线显得没有野心，全是长线让读者疲于等待。

检查方法：将伏笔列表对照章纲时间线，确认每条伏笔从铺设到回收之间有足够的间隔（不能同章铺设同章回收），又在读者还能记住的范围内（不能隔得太远）。

#### 维度 6：视角分配

检查各章节视角的分配是否合理。

- **主角权重**：主角视角的章节是否占多数？如果配角视角章节过多，读者会失去对主角的代入感。
- **配角视角的必要性**：每个配角视角章节是否有独立的信息价值（读者通过这个视角获得了其他视角无法获得的信息）？如果没有，考虑合并到主角视角。
- **视角切换频率**：同一章内是否频繁切换视角？避免在同一章中切换超过 2 个视角（除非是有意设计的多视角章节）。
- **视角与秘密**：某个角色的秘密是否恰好是在该角色视角的章节中透露的？利用视角来管理信息——在角色自己的视角中可以展现内心活动，在他人视角中只能展现外部表现。

检查方法：统计每章的视角，确认主角视角占比合理，配角视角每次使用都有明确目的。

#### 维度 7：章末拉力质量

检查每章的章末拉力是否足够强，是否能驱动读者点击下一章。

- **拉力类型多样性**：是否合理使用了不同类型的拉力（悬念、危机、反打、承诺、情感钩子、余韵）？连续使用同一种拉力类型会让读者疲劳。
- **拉力强度**：每章的拉力是否足够强？弱的拉力（"他们会继续排练"）vs 强的拉力（"她的谎言被听到了——会被戳穿吗"）。如果连续多章拉力偏弱，读者流失风险高。
- **拉力与下一章的承接**：章末拉力暗示的方向是否与下一章的实际内容一致？如果拉力暗示"A 的秘密要被发现"但下一章完全不提 A，就是承接断裂。
- **拉力闭环**：上一章的拉力是否在下一章得到了回应？不需要完全解决——但需要被提及或推进。拉力悬而未决超过两章就会变成"断线"。

检查方法：逐章阅读章末拉力，问"如果我是读者，看完这一章后我想不想点下一章？"诚实回答。

---

### Verdict 标准

审查完成后，对每个维度给出独立评级，然后汇总。

| 维度 | 评级 |
|------|------|
| 概念对齐 | 通过 / 有条件通过 / 不通过 |
| 支柱合规 | 通过 / 有条件通过 / 不通过 |
| 人物一致性 | 通过 / 有条件通过 / 不通过 |
| 结构完整性 | 通过 / 有条件通过 / 不通过 |
| 伏笔与回收 | 通过 / 有条件通过 / 不通过 |
| 视角分配 | 通过 / 有条件通过 / 不通过 |
| 章末拉力 | 通过 / 有条件通过 / 不通过 |

**总体 Verdict**：

| Verdict | 条件 | 行动 |
|---------|------|------|
| **APPROVED** | 全部维度通过，或仅 1 个维度有条件通过 | 可进入写作阶段 |
| **CONDITIONAL** | 2-3 个维度有条件通过，或 1 个维度不通过 | 修复指定维度后可进入写作 |
| **REJECTED** | 3+ 个维度有条件通过，或 2+ 个维度不通过 | 需要大幅修改大纲后再审查 |

### 与 gate-check 的关系

- `review-outline` 是**深度审查**：逐章逐维检查，发现具体问题，给出修复建议。用于大纲完成后的质量把关。
- `gate-check` 是**阶段门控**：检查阶段产出是否完整，决定是否允许进入下一阶段。用于流程控制。

建议流程：先运行 `review-outline` 修复问题，再运行 `gate-check` 确认通过。
