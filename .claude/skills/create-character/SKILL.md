当此技能被调用时：

1. **解析参数**：如果用户指定了角色名，优先创建该角色。如果 `all` 或无参数，按主角→配角→反派的顺序逐个创建。
2. **收集上下文**：读取 `design/novel/concept.md` 和 `design/novel/pillars.md` 获取故事背景和支柱约束。
3. **检查现有档案**：扫描 `design/novel/characters/` 下已有的档案，避免重复创建。
4. **交互式运行**，每个角色一个 Phase 循环。不要静默生成所有内容。

---

### Phase 1: 人物清单确认

从概念文档中提取人物清单，与用户确认创建顺序。

如果概念文档中已有明确的人物列表，展示并询问：
- 先创建谁？（默认：主角）
- 是否需要创建所有主要人物？（默认：是）
- 是否有概念文档中未提及的重要人物需要补充？

使用 `AskUserQuestion` 确认。

---

### Phase 2: 主角深挖

主角是故事的锚点，必须先做。以下每个维度逐一深入，不要跳过。

#### 2.1 核心驱动力

基于概念文档中已有的人物信息，与用户协作深化：

- **短期目标**（当前最想做的事，对应开篇状态）：
- **中期目标**（本卷要完成的事）：
- **长期目标**（全书终点）：
- **外部阻碍**（谁/什么在阻止她）：
- **内部阻碍**（她自身的什么在拖后腿——恐惧、性格缺陷、错误信念）：
- **目标的代价**（达不成会怎样？为什么读者要在乎？）：

**关键追问**：主角的"想要"和"需要"之间有什么差距？她以为自己想要什么？她实际需要什么？——这两个答案的差距就是弧光的空间。

#### 2.2 人物弧光

- **起点状态**（开局时是什么样的人——用 1-2 个具体场景描述，不要抽象概括）：
- **关键转折点**（什么事件迫使她开始改变——不能只是一个"顿悟"，必须有具体触发）：
- **终点状态**（故事结束后会变成什么样的人——与起点形成对照）：
- **变化的核心驱动力**（内在驱动还是外在推动？什么让她不能回到原来的状态？）：

使用 `AskUserQuestion` 确认弧光是否与概念文档的支柱一致。

#### 2.3 声音档案

声音是人物辨识度的核心。目标是：读者不看提示词就知道是谁在说话。

- **口头禅/惯用语**（如果有）：
- **句式偏好**（短句/长句/反问/感叹/省略——她会把话说满还是说一半？）：
- **说话节奏**（快/慢/停顿多——她是一个想好了才开口的人，还是边说边想？）：
- **情绪表达方式**（直接/含蓄/讽刺/用行动代替语言——她生气时是爆发还是安静？）：
- **不同情境下的声音**（至少覆盖四个情境：紧张/愤怒/开心/面对在意的人）：

每个情境给出一个示例对话。这比描述更有效。

#### 2.4 情绪范围

- **默认情绪状态**（她大部分时间给人的感觉是什么——不是"面无表情"或"开朗"，而是更具体的氛围词）：
- **情绪波动幅度**（稳定/偶尔波动/剧烈——她是一个情绪写在脸上的人，还是深藏不露？）：
- **情绪触发点**（什么情境/什么话/什么人会打破她的默认状态？）：
- **情绪恢复方式**（她怎么处理强烈情绪？独处/找人说话/弹琴/跑步/吃东西？）：

#### 2.5 身体与外貌

- **外貌特征**（3-5 个关键标签——不要只描写全身（身材、面容、发色），还要写最有辨识度的点）：
- **身体习惯**（紧张时会做什么小动作？放松时是什么姿态？）：
- **体能相关**（与她的职业/技能/角色定位相关的身体特征——比如剑客的握剑手、舞者的脚踝、程序员的肩颈）：

#### 2.6 秘密与已知信息

这是驱动故事的核心——每个人物带进故事的信息不对称。

- **她知道的**（她掌握但别人不知道的信息）：
- **她不知道的**（别人掌握但她不知道的信息——尤其是关于她自己的）：
- **她误判的**（她以为是真的、但实际是错的——这些误判是冲突的种子）：

使用 `AskUserQuestion` 确认主角档案的核心要素（弧光、声音、秘密），写入档案。然后再进入配角。

### Phase 4: 关系网总览

所有人物档案完成后，生成关系矩阵。使用实际角色名替换占位符：

|  | 角色A | 角色B | 角色C | 角色D |
|------|------|------|------|------|
| **角色A** | — | | | |
| **角色B** | | — | | |
| **角色C** | | | — | |
| **角色D** | | | | — |

每个交叉格填写：
- 关系性质（一句话）
- 当前温度（-10 到 +10）
- 不对称认知（A 以为 vs B 实际）

关系网检查：
- 是否存在单向关系而没有回应的？（每个单向关系必须有对应的"不知情"或"无回应"标注）
- 是否存在冲突/同盟的自然组合？（哪些关系天然会碰撞，哪些会互相支持）
- 关系变化的时间线是否合理？（温度变化必须有事件支撑）

使用 `AskUserQuestion` 确认关系网。

---

### Phase 5: 生成档案文件

使用模板 `.claude/docs/templates/character-sheet.md` 生成每个角色的档案文件。

输出路径：
- 主角：`design/novel/characters/protagonist.md`
- 配角：`design/novel/characters/supporting/[name].md`
- 反派/暗线人物：`design/novel/characters/antagonist.md` 或 `design/novel/characters/supporting/[name].md`

每个档案文件必须包含：
1. 基本信息
2. 核心驱动力（目标 + 阻碍）
3. 人物弧光
4. 声音档案（含不同情境示例对话）
5. 关系网（本角色与其他人的所有关系）
6. 身体状态
7. 情绪范围
8. 秘密与已知信息
9. 审查检查点

使用 `AskUserQuestion` 请求写入批准。每个角色单独请求，不要批量写入。
